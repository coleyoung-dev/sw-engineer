Android 기기 로그는 짧은 시간에 많은 줄이 들어올 수 있습니다. 수신 이벤트마다 WPF 컬렉션을 갱신하면 화면 작업이 지나치게 잦아지므로, 로그 수집과 화면 반영을 분리했습니다.

## 수집과 화면 반영

`LogcatSession`은 기기별 `adb logcat -v threadtime` 프로세스를 실행하고 출력 라인을 파싱합니다. 수신한 항목은 잠금으로 보호하는 대기 목록에 넣습니다. `DispatcherTimer`가 100ms마다 대기 항목을 꺼내 UI에 한 묶음으로 전달합니다.

ViewModel은 묶음 단위로 필터를 적용하고 `RangeObservableCollection`에 반영합니다. 전체 로그와 화면 표시 로그 모두 최대 항목 수를 제한해 장시간 사용 시 목록이 계속 커지지 않도록 했습니다. 일시정지 중에도 수집한 로그는 내부 목록에 남기고, 재개할 때 필터 결과를 다시 구성합니다.

프로세스가 종료되거나 창이 닫히면 이벤트 구독과 프로세스를 정리합니다. 이 경계를 통해 백그라운드 출력 처리와 WPF UI 갱신 책임을 나눴습니다.
