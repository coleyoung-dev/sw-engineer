Mobile 간판 인식은 현대백화점 면세점 AR 어드벤처 패스의 브랜드 캐처 콘텐츠에서 사용자가 매장 간판을 카메라로 비추면 해당 브랜드를 판별하고, 인식 결과에 따라 AR 연출과 미션 진행 상태를 갱신하는 기능입니다. Unity 클라이언트에서는 모바일 카메라 프레임을 인식 파이프라인에 넘기고, 추론 결과를 콘텐츠 상태와 UI 피드백으로 연결하는 흐름을 담당했습니다.

## 간단 로직

- 카메라 프레임에서 인식에 사용할 영역을 정리하고 입력 이미지 크기와 포맷을 모델 조건에 맞게 변환했습니다.
- TFLite 기반 분류 결과에서 가장 높은 confidence의 브랜드 후보를 선택했습니다.
- confidence가 기준값 이상일 때만 인식 성공으로 처리해 흔들림, 조명 변화, 유사 간판에서 생길 수 있는 오탐을 줄였습니다.
- 성공한 브랜드 ID를 미션 데이터와 매칭하고, AR 오브젝트와 UI 상태를 갱신했습니다.

## 상세 로직 구조

![Mobile 간판 인식 상세 로직](images_videos/hyundai/mobile/brand-catcher-logic.png)

상세 로직은 카메라 입력, 전처리, TFLite 추론, 결과 안정화, 콘텐츠 반영 단계로 나누어 구성했습니다. 모바일 기기에서 매 프레임 무겁게 추론을 돌리면 발열과 프레임 드랍이 생기기 쉬워서, 인식 요청 주기와 처리 상태를 제어하는 방식으로 Unity 렌더링 루프와 추론 루프가 서로 밀리지 않도록 했습니다.

전처리 단계에서는 카메라 텍스처에서 모델 입력에 필요한 크기로 리사이즈하고, RGB 채널 순서와 normalize 조건을 맞춥니다. 이후 TFLite interpreter에 tensor를 전달해 브랜드별 score를 얻고, 가장 높은 score와 threshold를 비교합니다. 임계값을 넘지 못하면 즉시 실패로 확정하지 않고 다음 입력을 기다리며, 일정 시간 안에 같은 브랜드가 반복해서 잡힐 때 성공 이벤트를 발생시키는 식으로 안정성을 높였습니다.

인식 성공 후에는 결과를 단순 텍스트로 보여주는 데서 끝내지 않고, 브랜드 캐처의 미션 상태와 연결했습니다. 이미 획득한 브랜드인지, 현재 활성 미션 대상인지, 보상 연출을 실행해야 하는지 등을 확인한 뒤 AR 콘텐츠, 사운드, UI를 순서대로 갱신했습니다. 이 과정에서 네이티브 앱 안에 Unity가 임베드되는 환경을 고려해 앱 상태 전환, 카메라 권한, 일시정지/복귀 케이스도 함께 확인했습니다.

## 구현 포인트

- TFLite 추론은 렌더링 흐름을 막지 않도록 요청 상태와 실행 주기를 분리했습니다.
- 인식 결과는 confidence threshold와 반복 감지 조건을 함께 사용해 안정화했습니다.
- 브랜드 ID를 미션 데이터와 매칭해 AR 반응, UI, 보상 상태가 같은 기준으로 움직이도록 구성했습니다.
- 카메라 권한, 앱 일시정지, Unity Embedded 상태 전환처럼 모바일 운영 단계에서 자주 발생하는 예외를 함께 점검했습니다.
